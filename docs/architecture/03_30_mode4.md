# AgentShield Clean 03_30 Mode 4

## Goal

Close the remaining command-loop items from the Clean CLI design:

```text
agentshield check --dry-run
agentshield baseline update
agentshield report
```

Mode 4 turns the shipped CLI from a one-shot checker into a maintainable local tool with baseline state and run history.

## In Scope

- `check --dry-run`
- auto-create initial per-module baselines after a real check run
- `baseline update --module <path>`
- `report --last N --module <path>`
- `.agentshield/baselines/*.json`
- `.qa-agent/runs/*.json` history rendering

## Runtime Behavior

### `agentshield check --dry-run`

- runs the configured checks
- writes the normal run record to `.qa-agent/runs/`
- skips webhook delivery
- skips baseline writes

### Real `agentshield check`

- runs checks concurrently
- writes `.qa-agent/runs/<timestamp>.json`
- auto-creates missing per-module baselines on first successful file-backed workflow

### `agentshield baseline update`

- reads `.qa-agent/runs/latest.json`
- shows current baseline summary versus latest run summary
- confirms with the user
- writes one file per module under `.agentshield/baselines/`

### `agentshield report`

- reads recent run files under `.qa-agent/runs/`
- sorts newest first
- optionally filters to one module
- prints pass/fail trend summaries in the terminal

## Notes

- Baseline files currently snapshot per-module check status, source run, and command metadata.
- Coverage-threshold gating is still a later layer on top of this baseline foundation.
- Public onboarding still centers on `init` and `check`; maintenance commands stay secondary.
